# 基本設計

## 1. システム概要

家庭で飼育しているウサギの飼育環境を監視するシステムを構築する。

温度・湿度センサーから定期的に環境情報を取得し、STM32で測定値を処理する。

取得した情報はESP32-C3を使用してWi-Fi経由で中継サーバーへ送信する。中継サーバーがLINE Messaging APIを通じてスマートフォンへ通知する。LINEからの操作は中継サーバーが受け、次の測定周期でESP32-C3からSTM32へ渡す。

また、本体にはLCDを接続し、現在の温度・湿度を表示する。

---

## 2. システム構成

```text
                 ┌───────────────────┐
                 │    SHT31          │
                 │ 温度・湿度センサー  │
                 └──────┬────────────┘
                        │ I2C
                        ↓
                 ┌───────────────┐
                 │    STM32      │
                 │ 測定・判定処理 │
                 └───┬──────┬────┘
                     │      │
                 I2C │      │ 通信
                     ↓      ↓
              ┌────────┐ ┌──────────┐
              │ LCD    │ │ ESP32-C3 │
              │ST7032i │ └────┬─────┘
              └────────┘      │
                              │ Wi-Fi
                              ↓
                     ┌─────────────────┐
                     │   中継サーバー   │
                     └────────┬────────┘
                              │ HTTPS
                              ↓
                     ┌─────────────────┐
                     │ LINE Messaging  │
                     │      API        │
                     └────────┬────────┘
                              │
                              ↓
                       ┌───────────────┐
                       │ スマートフォン │
                       └───────────────┘
```

## 3. 使用部品

| 部品          | 役割         | 備考                         |
| ----------- | ---------- | -------------------------- |
| STM32       | メイン制御・測定処理 | 温湿度取得、判定、LCD制御、LINE操作の適用 |
| ESP32-C3    | ネットワーク通信   | Wi-Fi、中継サーバーとのHTTPS       |
| SHT31       | 温度・湿度測定    | I2C接続                      |
| ST7032i LCD | 状態表示       | I2C接続、バックライトなし             |
| 中継サーバー    | LINEとの仲介    | Webhookの受付、通知の送信           |
| モバイルバッテリー等  | 電源         | 長時間稼働を検討                   |

## 4. 各部品の役割

### 4.1 STM32

システムのメイン制御を担当する。

#### 主な処理
・SHT31から温度を取得
・SHT31から湿度を取得
・温度・湿度の異常判定
・異常状態の管理
・LCDへの表示
・ESP32-C3への測定結果の送信
・ESP32-C3から受け取ったLINE操作の適用
・操作への返答
・測定タイミングの管理

### 4.2 SHT31

温度・湿度を測定する。

STM32とはI2Cで通信する。

#### 主な取得情報
温度
相対湿度

#### 測定間隔

約10分間隔を基本とする。

### 4.3 ESP32-C3

ネットワーク通信を担当する。

STM32から受け取った情報をWi-Fi経由で中継サーバーへ送信する。中継サーバーから受け取ったLINE操作をSTM32へ渡す。

#### 主な処理
・Wi-Fi接続
・中継サーバーとのHTTPS通信
・中継サーバーから受け取った操作のSTM32への通知
・STM32からの測定結果と通知の中継サーバーへの送信
・Wi-Fi切断時の再接続

### 4.4 LCD

現在の飼育環境を本体上で確認するために使用する。

#### 表示内容

現在の飼育環境を本体上で確認するために使用する。

#### 表示内容

例：
```text
TEMP: 22.5 C / HUMI: 52.3 %
HIGH TEMP !!
```
正常時は下段には何も表示しない。

## 5. 通信方式

### 5.1 STM32 ⇔ SHT31

I2Cを使用する。

```text
STM32
  │
  │ I2C
  ↓
SHT31
```
温度・湿度データを取得する。

### 5.2 STM32 ⇔ LCD

I2Cを使用する。

```text
STM32
  │
  │ I2C
  ↓
ST7032i LCD
```
温度・湿度などの情報を表示する。

### 5.3 STM32 ⇔ ESP32-C3

STM32とESP32-C3の間で、温湿度データ、状態情報、LINE操作を連携する。

UARTを使用する。

```text
STM32
  │
  │ UART
  ↕
ESP32-C3
```

測定結果と状態はSTM32からESP32-C3へ渡す。LINEの操作はESP32-C3からSTM32へ渡す。ATにてコマンド送信する。

### 5.4 ESP32-C3 ⇔ 中継サーバー ⇔ LINE Messaging API

ESP32-C3はWi-Fiで中継サーバーとHTTPS通信する。LINE Messaging APIを呼ぶのは中継サーバーである。

```text
ESP32-C3
    ↓
 Wi-Fi
    ↓
中継サーバー
    ↓
LINE Messaging API
    ↓
スマートフォン
```

LINEからの操作は、中継サーバーがWebhookで受けて保管する。本体は約10分周期の接続で取得し、STM32へ渡す。

## 6. データ処理フロー

通常時は以下の処理を繰り返す。

```text
① ESP32-C3がWi-Fiへ接続し、中継サーバーから操作を取得
    ↓
② 操作をSTM32へ通知
    ↓
③ STM32が設定を適用
    ↓
④ SHT31から温度・湿度を取得
    ↓
⑤ STM32で異常判定
    ↓
⑥ LCDへ現在値を表示
    ↓
⑦ 測定結果と通知を中継サーバーへ送信
    ↓
⑧ 中継サーバーがLINE Messaging APIへ送信
    ↓
⑨ スマートフォンへ通知
    ↓
⑩ 次回測定まで待機
    ↓
①へ戻る
```

## 7. 測定周期

基本的な測定間隔は約10分とする。

```text
測定
 ↓
処理
 ↓
通知
 ↓
待機
 ↓
約10分後
 ↓
再測定
```

ただし、異常状態や生存確認については通常の測定周期とは別に処理する可能性がある。

## 8. 異常判定

STM32で温度・湿度の測定値を判定する。

### 温度

初期値：

| 温度レベル    |    危険度         | うさぎへの主なリスク・影響 |
| --------------- | --------------- | -------------------------------- |
|30℃ 以上     | 極めて危険 (猛暑) | 熱中症の危険性が非常に高い。短時間でも命に関わります。|
|26℃ ～ 29℃  | 危険 (高温)       | 食欲低下、呼吸が荒くなる。湿度が加わると熱中症を起こします。|
|18℃ ～ 25℃  | 安全・快適        | うさぎにとっての理想的な環境（ベストは20℃～22℃）。|
|10℃ ～ 17℃  | 注意 (低温)       | 子うさぎ、高齢、体調不良のうさぎは体力を消耗しやすくなります。|
|10℃ 未満     | 危険 (極寒)       | 低体温症、免疫力低下、お腹の動きが止まる「うっ滞」のリスク。|

※実際の閾値は検証結果により調整する。

### 湿度

|湿度レベル | 危険度            | うさぎへの主なリスク・影響
| --------------- | --------------- | -------------------------------- |
|70% 以上   | 非常に危険 (高湿) | 熱中症の急増（25℃前後でも発症）、皮膚炎、耳のカビ、ダニの繁殖
|60% ～ 69% | 注意              | 蒸し暑さによる食欲低下、胃腸の動きの悪化（うっ滞のリスク）
|40% ～ 60% | 安全・快適        | うさぎにとっての理想的な環境
|40% 未満   | 危険              |(乾燥)粘膜の乾燥、呼吸器感染症（スナッフル：くしゃみ・鼻水）の誘発

※実際の閾値は検証結果により調整する。

### 複合

温度と湿度を個別に判定するだけではなく、両方の状態を考慮して危険度を決定する。

| 温度＼湿度      | <40%     | 40～60%   | 61～69%   | >=70%     |
| ---------- | -------- | -------- | -------- | -------- |
| **<10℃**   | !! 危険    | !! 危険    | !! 危険    | !! 危険    |
| **10～17℃** | ! 注意    | ! 注意    | ! 注意    | !! 危険    |
| **18～21℃** | ! 注意    | 〇正常    | ! 注意    | !! 危険    |
| **22～25℃** | ! 注意    | 〇正常    | ! 注意    | !! 危険    |
| **26℃**    | !! 危険    | !! 危険    | !! 危険    | !!! 極めて危険 |
| **27～28℃** | !! 危険    | !! 危険    | !! 極めて危険 | !!! 極めて危険 |
| **29℃**    | !!! 極めて危険 | !!! 極めて危険 | !!! 極めて危険 | !!! 極めて危険 |
| **>=30℃**   | !!! 極めて危険 | !!! 極めて危険 | !!! 極めて危険 | !!! 極めて危険 |

初回はこの表は使用せず、温度、湿度の両方の状態を考慮して危険度を決定する。

例 : 
```text
温度：27℃
湿度：70%

        ↓

高温 ＋ 高湿度

        ↓

高い危険度として判定
```

## 10. 通知設計

例：
```text
【高温異常】

現在温度：28.5℃
湿度：65%

高温状態を検知しました。
```

## 10.2 通知抑制

同じ異常が継続している場合、毎回通知するのではなく通知頻度を制御する。

危険度に応じて通知間隔を変更できるようにする。

例：
| 危険度   | 通知例               |
| ----- | ----------------- |
| 注意    | 一定時間継続後に通知        |
| 危険    | 初回通知後、一定時間経過後に再通知 |
| 極めて危険 | 毎回通知              |

具体的な通知間隔は詳細設計で決定する。

## 11. 生存確認通知

停電を直接検知する機能は初期版では実装しない。

代わりに、30分ごとにスマートフォンへ生存確認通知を送信する。

例：
```text
【快適な環境】
温度：22.5℃
湿度：52.3%
```

この通知が予定時間を超えて届かない場合、
・停電
・Wi-Fi障害
・インターネット障害
・本体停止
・その他の通信障害

などの可能性があるものとして確認する。

## 12. Wi-Fi切断時の動作

```text
Wi-Fiが切断されても、温湿度測定は継続する。

Wi-Fi切断
    ↓
温湿度測定は継続
    ↓
Wi-Fi再接続を試行
    ↓
再接続成功
    ↓
必要な情報を送信
```

Wi-Fiが利用できない間は、LINE通知を行うことができないため、本体側で状態を保持する。

## 13. 電源設計

長期間の連続稼働を目的として、電源方式を検討する。

候補：

・USB等による有線電源
・モバイルバッテリー
・充電式バッテリー
・有線電源＋バックアップバッテリー

最終的な電源方式は、消費電力測定後に決定する。

## 14. 省電力設計

6か月程度の連続稼働を目標とする。

省電力化の方法として以下を検討する。

・ESP32-C3のスリープ
・STM32の低消費電力モード
・測定間隔を約10分とする
・必要な場合のみWi-Fi通信を行う
・LCDの消費電力を抑える
・通信回数を必要最小限にする

実際の消費電力を測定し、連続稼働時間を算出する。

## 15. エラー・障害時の基本方針

### SHT31通信エラー
・エラーを検知する
・再取得を試行する
・必要に応じてシステム異常として通知する

### Wi-Fi接続エラー
・再接続を試行する
・温湿度測定は継続する

### LINE通信エラー
・通知処理を失敗として記録する
・必要に応じて再送する

### STM32・ESP32間通信エラー
・通信エラーを検知する
・再通信を試行する

## 16. セキュリティ

LINE Messaging APIのチャネルアクセストークンとチャネルシークレットは、中継サーバーだけが持つ。ESP32-C3はLINE Messaging APIを呼ばない。

中継サーバーとの認証情報を含め、次の情報はソースコードや公開資料に直接記載しない。

・LINEチャネルアクセストークン
・LINEチャネルシークレット
・中継サーバーとの認証情報
・Wi-Fi SSID
・Wi-Fiパスワード
・その他の認証情報
