# 開発スケジュール

## 1. 全体方針

11月までに、実環境で利用可能な最低限のシステム（MVP）を完成させる。

開発は、以下の順番で進める。

1. 設計確定
2. 部品購入・単体動作確認
3. 基本システム統合
4. 異常判定・通知制御
5. 生存確認・通信異常対応
6. 省電力化
7. 実環境テスト

---

# 4. Phase 3：基本システム統合

**期間：10月中旬**

以下の構成を完成させる。

```text
SHT31
  ↓
STM32
  ↓
ESP32-C3
  ↓
Wi-Fi
  ↓
LINE Messaging API
  ↓
スマートフォン
```

## 作業

- [ ]  SHT31 → STM32の温湿度取得
- [ ]  STM32 → LCDへの表示
- [ ]  STM32 → ESP32-C3へのデータ連携
- [ ]  ESP32-C3 → Wi-Fi通信
- [ ]  ESP32-C3 → LINE Messaging APIへの通信
- [ ]  LINEへのテスト通知
- [ ]  10分間隔の測定処理
- [ ]  取得した温度・湿度をESP32-C3へ送信
- [ ]  取得した温度・湿度をLINEへ送信
- [ ]  一連の処理を連続して実行できることを確認

## 完了条件

以下の一連の処理が正常に動作すること。

SHT31
  ↓
温度・湿度を取得
  ↓
STM32
  ↓
ESP32-C3
  ↓
Wi-Fi
  ↓
LINE Messaging API
  ↓
スマートフォンに温度・湿度を通知

また、LCDにも温度・湿度が表示されること。

# 6. Phase 5：生存確認・通信異常対応

**期間：10月下旬**

## 生存確認

- [ ] 30分ごとの生存確認通知
- [ ] 生存確認通知のON/OFF
- [ ] 温度・湿度を生存確認通知に含める
- [ ] 通知内容の確認

## Wi-Fi異常

- [ ] Wi-Fi切断検知
- [ ] Wi-Fi再接続
- [ ] 再接続失敗時の動作
- [ ] Wi-Fi復旧後の通信
- [ ] 温湿度測定の継続

## 停電対応

- [ ] 停電の直接検知は実装しない
- [ ] 30分ごとの生存確認通知を代替手段とする
- [ ] 通知途絶時に考えられる原因を整理する

## 完了条件

30分ごとの生存確認通知により、本体が正常に動作していることを外出先から確認できる。

# 12. 優先順位

開発中に時間が足りなくなった場合は、以下の順番を優先する。

1. 温度測定
2. 湿度測定
3. 異常判定
4. LINE通知
5. 通知抑制
6. 生存確認通知
7. Wi-Fi再接続
8. LCD表示
9. 省電力化
10. その他の改善機能

カメラ・自動冷却・本格的な停電検知は、11月のMVP完成後に回す。
