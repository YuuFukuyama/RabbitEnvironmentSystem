# 要件定義

## 1. 目的

家庭で飼育しているウサギの飼育環境を監視し、外出中でも温度・湿度などの環境状態を確認できるシステムを構築する。

異常値を検知した場合には通知を行い、飼育環境の異常を早期に把握できるようにする。

---

## 2. ヒアリング項目

### 2.1 現状

* 現在、温度をどう確認している？
* どのくらいの頻度で確認している？
* 外出中に温度が気になることはある？
* 温度以外に気になるものはある？

### 2.2 困りごと

* 今の方法で困っていることは？
* 夏場に不安なことは？
* 外出中に知りたい情報は？

### 2.3 要求

* どうなったら便利？
* 通知は必要？
* スマホから確認したい？
* 過去の記録は必要？
* カメラは必要？
* 湿度も必要？

### 2.4 運用

* 24時間動かしたい？
* 停電した場合は？
* Wi-Fiが切れた場合は？
* メンテナンスはどのくらいなら許容できる？

# 7. 温度・湿度監視仕様

## 7.1 測定間隔

温度・湿度の環境チェックは、**約10分間隔**で実施する。

## 7.2 温度閾値

初期値として以下を設定する。

| 状態   |       温度条件 |
| ---- | ---------: |
| 低温異常 |      15℃未満 |
| 低温警告 | 15℃以上18℃未満 |
| 正常   | 18℃以上24℃以下 |
| 高温警告 |  24℃超27℃以下 |
| 高温異常 |       27℃超 |

※閾値は初期設定値とし、実際の飼育環境での運用結果をもとに調整する。

## 7.3 異常判定

一時的な温度変化による誤通知を防止するため、異常値を複数回連続して検出した場合に通知する。

初期仕様：

* 測定間隔：10分
* 異常判定：3回連続
* 異常通知までの時間：約30分

## 7.4 ヒステリシス

異常状態と正常状態の境界付近で通知が繰り返されることを防止するため、警告開始条件と解除条件を分ける。

| 状態   | 開始条件  | 解除条件  |
| ---- | ----- | ----- |
| 低温警告 | 15℃未満 | 16℃以上 |
| 高温警告 | 27℃超  | 26℃未満 |

# 8. 通知仕様

## 8.1 通知対象

以下の状態を通知対象とする。

* 高温異常
* 低温異常
* 湿度異常
* 停電
* その他システム異常

## 8.2 通知抑制

同じ異常が継続している場合、一定間隔で通知を繰り返すのではなく、異常発生時に通知し、その後は状態が復帰するまで通知を抑制する方式を基本とする。

具体的な再通知条件は詳細設計で決定する。

---

# 9. 電源・停電

## 9.1 電源

長期間の連続稼働を実現するため、電源方式について検討する。

候補：

* USB等による有線電源
* バッテリー
* 充電式バッテリー
* 有線電源＋バックアップバッテリー

## 9.2 停電検知

停電発生時にも通知できるよう、停電を検知する仕組みを構築する。

停電時の通信方法およびバックアップ電源については、システム設計で決定する。

# 10. ネットワーク

## 10.1 通常時

ESP32を使用してWi-Fiに接続し、温湿度データおよび異常情報を中継サーバーへ送信する。中継サーバーがLINE Messaging APIを通じてスマートフォンへ通知する。

状態の確認と操作はLINEで行う。LINEからの操作は中継サーバーが受け、次の約10分周期の測定時にESP32からSTM32へ渡して反映する。

電源投入とリセットのあと、STM32は最初に中継と通信できたときに現在時刻と、誰か定期通知がONかを受け取る。STOPからの復帰では受け取らない。LINEで定期通知を切り替えても、本体はリセットまでそのモードを変えない。

## 10.2 Wi-Fi切断時

Wi-Fiが切断された場合でも、STM32による温湿度測定は継続できる構成とする。

Wi-Fi復旧後に必要に応じて状態を再送信する。

# 11. 納期

初期目標として、**11月までに必須機能を実装し、実環境での運用を開始する。**

優先順位：

1. 温度測定

3. 異常判定
4. 通知
5. アプリからの状態確認
6. 停電検知
7. その他の改善機能
