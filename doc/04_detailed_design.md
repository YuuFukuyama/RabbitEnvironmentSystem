# 詳細設計（たたき台）

## 1. 詳細設計の目的

基本設計で決定したシステム構成をもとに、各機能の具体的な処理方法、通信方法、データ形式、状態管理方法を定義する。

本資料では、実装時に必要となる仕様を可能な限り具体化する。

---

# 2. システム構成

## 2.1 全体構成

```text
                    ┌──────────────┐
                    │    SHT31     │
                    │ 温度・湿度測定 │
                    └──────┬───────┘
                           │ I2C
                           ↓
                    ┌──────────────┐
                    │    STM32     │
                    │ ・測定       │
                    │ ・異常判定   │
                    │ ・状態管理   │
                    │ ・LCD制御    │
                    └───┬──────┬───┘
                        │      │
                    I2C │      │ UART等
                        ↓      ↓
                 ┌────────┐ ┌──────────┐
                 │ ST7032i│ │ ESP32-C3 │
                 │  LCD   │ └────┬─────┘
                 └────────┘      │
                                 │ Wi-Fi
                                 ↓
                         ┌────────────────┐
                         │ LINE Messaging │
                         │      API       │
                         └───────┬────────┘
                                 │
                                 ↓
                           スマートフォン
```

# 3. STM32詳細設計

## 3.1 STM32の役割

STM32をシステムのメイン制御部とする。

主な処理：

- SHT31から温湿度を取得
- 温湿度の異常判定
- 異常状態の管理
- LCDへの表示
- ESP32-C3へのデータ送信
- 測定周期の管理
- 通知要求の生成
- システム状態の管理

---

# 4. SHT31詳細設計

## 4.1 接続方式

STM32とSHT31をI2Cで接続する。

```text
STM32              SHT31

SCL  ───────────── SCL
SDA  ───────────── SDA
3.3V ───────────── VIN
GND  ───────────── GND
```

## 4.2 I2Cアドレス

SHT31のI2Cアドレスは以下を使用する。

```text
初期値：0x44
```

※使用するブレークアウト基板のADR設定を確認する。

---

## 4.3 測定周期

基本測定周期：

```text
10分
```

測定処理：

```text
測定開始
 ↓
SHT31へ測定要求
 ↓
温度・湿度取得
 ↓
データチェック
 ↓
異常判定
 ↓
LCD更新
 ↓
ESP32-C3へデータ送信
 ↓
待機
```

---

## 4.4 センサーデータ

| 項目 | 型 | 単位 |
|---|---|---|
| temperature | float | ℃ |
| humidity | float | %RH |
| timestamp | unsigned long等 | 時刻 |
| sensor_status | enum | センサー状態 |

# 5. 温度・湿度異常判定

## 5.1 温度判定

| 状態 | 条件 |
|---|---|
| 低温異常 | 15℃未満 |
| 低温警告 | 15℃以上18℃未満 |
| 正常 | 18℃以上24℃以下 |
| 高温警告 | 24℃超27℃以下 |
| 高温異常 | 27℃超 |

※実環境テストで閾値を再検討する。

HUMIDITY_LOW

# 7. 温湿度複合判定

温度と湿度を個別に判定した後、両方の状態を組み合わせて総合状態を決定する。

例：

```text
温度：正常
湿度：正常
↓
総合：正常
```

```text
温度：高温警告
湿度：高湿度
↓
総合：危険
```

```text
温度：高温異常
湿度：高湿度
↓
総合：極めて危険
```

詳細な組み合わせ表は検証結果をもとに決定する。

---

# 8. 異常判定の継続条件

一時的なセンサー値の変化による誤通知を防止する。

基本測定周期が10分の場合：

```text
異常値
 ↓
10分後：異常
 ↓
20分後：異常
 ↓
30分後：異常
 ↓
異常確定
```

初期仕様：

```text
3回連続異常
```

「注意」分類のみこちらの使用を適用する。

# 11. 通知制御

## 11.1 通知の基本ルール

```text
異常発生通知
継続通知
正常復帰通知
生存確認通知
システム異常通知
```

## 11.2 通知抑制

同一異常が継続している場合、毎回通知しない。

```text
正常
 ↓
高温異常
 ↓
異常発生通知
 ↓
異常継続
 ↓
通知抑制
 ↓
設定時間経過
 ↓
再通知
```

## 11.3 通知レベル

| 危険度 | 通知方式 |
|---|---|
| 注意 | 一定時間継続後に通知 |
| 危険 | 初回通知後、一定時間経過で再通知 |
| 極めて危険 | 毎回通知 |

具体的な通知間隔：

### 注意
初回は通知しない。
３回検知で通知。
検知後、３０分経過で再度通知。
初回から１時間経過で[危険]に上げる。

### 危険
２０分毎に通知
３０分経過で[「]極めて危険]に上げる。

### 極めて危険
毎回通知。

# 12. 正常復帰通知

# 14. STM32 ⇔ ESP32-C3通信

通信方式：

```text
候補：UART
```

UARTを第一候補とする。

理由：

- 構成がシンプル
- デバッグしやすい
- STM32とESP32-C3の通信に適している

## 14.1 データ形式

ATを使用。

# 16. Wi-Fi切断時の動作

Wi-Fiが切断されても、STM32による温湿度測定は継続する。

```text
Wi-Fi切断
 ↓
ESP32-C3が再接続
 ↓
成功
 ↓
最新状態を送信
```

Wi-Fi切断中に発生した異常については、必要な情報をSTM32側で保持する。

# 19. 生存確認機能

30分ごとにLINEへ生存確認通知を送信する。

```text
起動
 ↓
30分経過
 ↓
生存確認通知
 ↓
30分経過
 ↓
生存確認通知
 ↓
繰り返し
```

生存確認通知はON/OFFできるようにする。

---

# 20. 停電への対応

初期版では停電を直接検知しない。

代替として30分ごとの生存確認通知を利用する。

通知が届かなくなった場合は、

```text
停電
または
Wi-Fi障害
または
インターネット障害
または
本体停止
```

などの可能性がある。

したがって、システム上は「通知が届かない＝停電」と断定しない。

# 22. LCD通信

ST7032i LCDとSTM32をI2Cで接続する。

```text
STM32
 ├── SCL ── SHT31
 └── SDA ── SHT31

STM32
 ├── SCL ── ST7032i
 └── SDA ── ST7032i
```

※同一I2Cバスを使用する場合は、各デバイスのI2Cアドレスが重複しないことを確認する。

---

# 23. I2Cプルアップ抵抗

I2CのSCLおよびSDAにはプルアップ抵抗が必要。

抵抗値は、

- I2C通信速度
- バス容量
- 接続デバイス数
- 使用する基板の内蔵プルアップ抵抗

などを考慮して決定する。

初期候補：

```text
4.7kΩ
```

ただし、SHT31やにプルアップ抵抗が実装されている場合は、合成抵抗値を確認する。

# 25. 消費電力設計

消費電力の大きい処理として特にWi-Fi通信を考慮する。

```text
待機
 ↓
測定
 ↓
Wi-Fi起動
 ↓
通信
 ↓
Wi-Fi停止 / スリープ
 ↓
待機
```

可能であれば通信回数を減らし、省電力化する。

# 26. 10分間隔測定処理

```text
[起動]
   ↓
[SHT31測定]
   ↓
[異常判定]
   ↓
[LCD更新]
   ↓
[ESP32-C3へ送信]
   ↓
[必要ならLINE通知]
   ↓
[待機]
   ↓
[10分後]
   ↓
[SHT31測定]
```

# 27. 30分生存確認処理

10分周期の測定とは別に、30分周期で生存確認を行う。

```text
10分：測定
20分：測定
30分：測定＋生存確認通知
40分：測定
50分：測定
60分：測定＋生存確認通知
```
