# 3. 合否の正本

期待結果の数値と通知のタイミングは [04_detailed_design.md](04_detailed_design.md) に従う。合否は詳細設計どおりとする。

T-01 の精度比較は [firmware/gy-sht31-d.md](../firmware/gy-sht31-d.md) の ±0.3℃・±2 %RH（推奨範囲内）。境界はダミー（T-10 / T-11、実施済み）で見た。

---

# 4. 段階

単体・結合・システム・実環境の区分は、7 章の各ケースに書く。飼育場所では危険な温湿度を作らない。

---

# 5. 環境

実施のたびに、実施日・場所・基板構成・ファーム識別・`ENV_SENSOR_USE_DUMMY` ON/OFF を残す。

ダミー ON の結果は本番合格に使わない（T-10 / T-11 の判定用ダミーを除く）。UART は見ず、LCD・LED・LINE・中継で観測する。LINE の push が月間上限などで届かないときは、中継 KV の送信履歴（`push-log`、LINE「送信履歴」または `GET /v1/push-log`）を push の代替観測とする。到達確認は別途済みとする。

---

# 6. ケースの見方

定義は 7 章、合否は 10 章。合否は合格・不合格・未実施（理由あり）。

未決定の数値（再接続秒数、再送回数など）の一致は合格条件にしない。詳細設計 32 章の未決定項目も合格条件にしない。

総合 DANGER、片側解除のヒステリシス、DANGER/CRITICAL への時間昇格、CRITICAL 周期通知、中継 11.4 の push 省略、401・未許可 LINE、インターネットのみ切断は、本書では個別ケースにしない。
