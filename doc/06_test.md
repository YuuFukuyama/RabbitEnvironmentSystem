この文書は、何を、どの条件で、どうなれば合格かを書く。実施時期は [02_schedule.md](02_schedule.md) に残し、ここへ作業チェックは写さない。

# 3. 合否の正本

期待結果の数値と通知のタイミングは [04_detailed_design.md](04_detailed_design.md) に従う。

閾値、WARNING の通知までの時間、停電の直接検知は、要件定義・基本設計と詳細設計で異なる。合否は詳細設計どおりとし、要件側の改訂は別課題とする。

温度・湿度の比較に使う精度は、[firmware/gy-sht31-d.md](../firmware/gy-sht31-d.md) の販売ページ記載（温度 ±0.3℃、湿度 ±2 %RH）とする。この比較は推奨範囲（5〜60℃、20〜80 %RH）の T-01 に限る。10℃や 15 %RH などの境界は、ダミーの値で危険度を見る。

# 4. 段階


| 段階   | 見ること                                |
| ---- | ----------------------------------- |
| 単体   | SHT31 の測定、LCD の表示、危険度の境界            |
| 結合   | 測定、LCD、中継の履歴、LINE まで一連で届くこと         |
| システム | 抑制、復帰、起動時の取得、定期通知、Wi-Fi とインターネットの切断 |
| 実環境  | 飼育場所での連続運転、有線時のコードの取り回し             |


境界の多数ケース（T-10〜T-15、T-60、T-61）は、ダミーで値を変えて判定と LCD だけ先に見てよい。長時間の昇格と定期通知（T-21、T-22、T-32、T-40）は、実時間で 1 本ずつ通す。

飼育場所では、ウサギに危険な温度・湿度を作らない。異常通知の実時間確認は、実験条件のケースで行う。

# 6. ケースの見方

1 件の定義は 7 章、合否・実施日・実測は 10 章に書く。

合否は次のいずれかとする。

- 合格
- 不合格
- 未実施（実測メモに理由）

操作は、加熱、湿度の変化、ダミーの値、Wi-Fi のオフ、リセット、LINE のボタンなど、外から観測できるものに限る。HAL の内部手順は書かない。

再接続の待機秒数、LINE の再送回数、UART 速度、プルアップ抵抗値、バッテリー容量は未決定である。これらの数値の一致は合格条件にしない。決まった動作（測定が続く、復旧後は最新だけ送る、など）だけを見る。

# 12. 合格条件にしない項目

詳細設計 32 章で未決定のものは、決まった仕様であるかのように合格条件へ入れない。

- UART 通信速度
- ESP32-C3 の AT ファームウェア、コマンドセット、応答仕様
- STM32 と ESP32-C3 のあいだのデータ表現、タイムアウト
- Wi-Fi 再接続間隔
- ESP32-C3 のスリープ方式
- LINE 通信失敗時の再送回数、再送間隔
- LINE 詳細ログを分割するときのメッセージサイズと送信間隔
- I2C プルアップ抵抗値
- 電源回路
- バッテリー容量
- RAM ログの記録サイズ

仕様の全文、回路、実装手順、スケジュールの日程は、この文書へ写さない。
